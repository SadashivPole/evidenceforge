# EvidenceForge v0.1.0-alpha.1 - Developer Preview

**Release channel: Alpha developer preview. This is not a stable or production release.**

## Overview

EvidenceForge is a local-first development workbench for security-questionnaire evidence, provenance, deterministic grounding, response history, and explicit human review. It is not a compliance certification, autonomous answer-generation system, or automatic questionnaire-submission product.

## Included in this preview

- Workspace- and membership-scoped API authorization with opaque bearer-token authentication.
- Deterministic XLSX questionnaire import and versioned question snapshots.
- Evidence documents, versions, chunks, and server-validated citation provenance.
- Workspace-scoped lexical/semantic grounding candidates.
- Persisted responses, immutable revisions, and explicit human review actions.
- Guided questionnaire browsing with search/filter controls and unsaved-change safeguards.
- PostgreSQL/pgvector persistence and a local Docker Compose quickstart.

## Important limitations and known risks

- **Alpha software:** no production security certification or external security audit is claimed.
- **Answer generation:** an end-to-end LLM answer-generation workflow is not implemented. Grounding returns evidence candidates; a human supplies and reviews response content.
- **Frontend deployment:** the current frontend container uses the Next.js development server. It is for local development, not a production-optimized deployment image.
- **Local runtime gates:** migration `0008` against the recovered demo database and live guided-page API/browser end-to-end checks have not been verified.
- **Question text provenance:** `source_question_text` contains parser-normalized wording, not byte-exact original XLSX cell text. Do not treat it as a raw-cell archive.
- **Large questionnaires:** the configured 5,000-question limit has not yet been profiled through the guided browser UI.
- **Async UI race risk:** selection changes during in-flight chooser requests still need browser E2E verification.
- **Frontend dependency advisory:** the full `npm audit` reports five high-severity findings through the `braces@3.0.3` dependency chain. `npm audit --omit=dev` reported zero vulnerabilities, but that alone does not prove the current development-server container excludes the affected tooling. The risk remains temporarily accepted pending reassessment by 2026-11-02. Do not use `npm audit fix --force` blindly.

## Quick start and contribution safety

Follow the repository [`README.md`](../../README.md) and [`CONTRIBUTING.md`](../../CONTRIBUTING.md). Copy `.env.example` to a local `.env`, replace the placeholder password, and never commit `.env`, tokens, logs containing secrets, database dumps, or recovered data. Follow [`SECURITY.md`](../../SECURITY.md) for vulnerability reporting.

## Recommended audience

Developers and security practitioners who want to inspect the implementation, run local experiments with synthetic evidence, and contribute focused tests. Do not use this alpha as an unattended compliance decision-maker or claim production-readiness on its basis alone.
