# Security Policy

## Supported versions

EvidenceForge is a developing workbench and does not currently publish a stable release-support matrix. Please report security issues that affect the latest repository revision. Fixes for older commits or unofficial forks are not guaranteed.

## Reporting a vulnerability

**Do not publish exploitable details, credentials, access tokens, personal data, or a proof of concept in a public issue.**

1. First check the repository's **Security** tab for **Report a vulnerability**. If private vulnerability reporting is enabled, use that private reporting form.
2. If the private reporting form is unavailable, open a low-detail public issue asking the maintainers for a private reporting channel. Do not include technical exploit details in that issue.
3. When a private channel is established, include the affected commit or version, impact, prerequisites, reproducible steps, and relevant logs with secrets and personal data removed.

A `SECURITY.md` file does not itself enable GitHub private vulnerability reporting. Repository administrators must enable that feature separately. Maintainers should enable it before inviting external security reports if it is available for this repository.

## Coordinated disclosure

Please allow the maintainers reasonable time to acknowledge and investigate a report before public disclosure. No fixed response or remediation service-level agreement is currently promised. Do not assume that a report has been received until the reporting channel confirms submission.
